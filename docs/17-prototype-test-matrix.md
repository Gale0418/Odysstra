# 17｜P-001 驗收案例、測試紀錄與範圍閘門

> **狀態：測試設計，全部 Not run（尚未執行）。** 本頁不是程式、測試報告或已完成清單。依 [09｜P-001](09-production-risks-and-prototypes.md) 與 [16｜邊界提案](16-playability-contracts.md) 建立；提案若未採用，相關案例標 Deferred，不得寫成已通過。

## 測試戰區與暫定條件

使用出發地、商港、軍閥要塞、無人採集系及返鄉出口等五個節點的測試版；這不是正式 30 個地標的替代品。至少有兩條可選路線，支援回頭。模擬時間、種子、起始艦隊、人口、資源和敵方初始任務均記錄在測試快照。

戰鬥先用少量艦艇驗證操作，再另外測 20／50／100 艘規模；未達到 100 艘的實測，不宣稱百艦效能已通過。資源初值、補給耗時、敵方速度等是**測試預設**，不是正式平衡承諾。

## 32 個可執行驗收案例（目前未執行）

### A｜遊戲時間與暫停

| ID | 操作／情境 | 預期可觀察結果 |
|---|---|---|
| QA-T01 | 正常運行後正式暫停，再恢復 | 暫停段原料消耗、我方建造、敵方調動均未前進；恢復後一起繼續 |
| QA-T02 | 同一輸入序列用不同速度，推到相同模擬時間 | 關鍵世界狀態一致；速度只改現實等待，不額外觸發一次事件 |
| QA-T03 | 若採 Web，切換背景、休眠後回來 | 按採納的暫停規則處理；不補算離線接管，不突然大幅扣油 |
| QA-T04 | 預約修船，停在配船／交易規劃頁，再確認 | 瀏覽資訊不免費修好船，也不多扣時間；採納的行動耗時只算一次 |

### B｜舊圖與世界狀態

| ID | 操作／情境 | 預期可觀察結果 |
|---|---|---|
| QA-M01 | 舊圖標友軍港，世界控制權已改變，再偵察 | 歷史記錄仍保留；最近現況與觀測日期更新，不冒充戰前就屬敵國 |
| QA-M02 | 只取得星門運作報告 | 星門情報變新，但庫存／駐軍／其餘未知欄位不被一鍵刷新 |
| QA-M03 | 同種子、相同世界時間，以不同順序開啟純資訊面板 | 已定的世界事實、隱藏內容與事件旗標不因 UI 順序重抽；不含真的派艦或推進時間 |
| QA-M04 | 港口已毀，離開再返回，讀回同一存檔 | 不重新生成完整港口；依賴港口存活的新任務不再觸發，過期廣播須標清楚 |

### C｜戰勝國調度

| ID | 操作／情境 | 預期可觀察結果 |
|---|---|---|
| QA-V01 | 低優先軍團位於偏遠系，同時另一處啟動高危資產 | 戰勝國仍能知道軍團位置，但在此測試條件下優先調兵處理高危目標 |
| QA-V02 | 同一軍團主動進入已有敵對巡邏的接管系 | 不因全局優先度低而獲得免戰；地方敵軍按交戰規則反應 |
| QA-V03 | 一支具名敵軍被派往 A，又出現 B 目標 | 不複製同一艦隊到兩處；改派須更新路線、任務與抵達時間 |
| QA-V04 | 玩家改變 UI 待執行航線，然後取消 | 敵軍不讀未執行的玩家心思；實際移動、攻擊或可觀察神器啟動才更新判斷 |

### D｜人口與返鄉

| ID | 操作／情境 | 預期可觀察結果 |
|---|---|---|
| QA-P01 | 減少載員後勤艦，建立一個仍符合操作需求的開局 | 實際開局人口依容量減少；未登艦者不被列為本局陣亡 |
| QA-P02 | 同一人口批次分遣、會合、轉船，再讀檔 | 原始同鄉總數守恆，沒有重複人員，船員與住民容量不重扣 |
| QA-P03 | 觸發同鄉救援，重複互動、讀檔後再查 | 同一救援只入帳一次；原始同鄉、救回同鄉、其他加入者分開 |
| QA-P04 | 比較不同起始人口的返鄉報告，部分人在分遣隊 | 同時顯示起始人數、返鄉絕對數及比例；仍在外者不算到家；到家仍 Happy End |

### E｜資源與行動結算

| ID | 操作／情境 | 預期可觀察結果 |
|---|---|---|
| QA-L01 | 購買補給並用列印機維持人口 | 交易與原料消耗可追溯，不憑空產生額外貨物供無限轉售 |
| QA-L02 | 採集到容量上限後繼續等待或取消 | 不溢出、不反向扣成負數；已耗時間與實際採集量一致 |
| QA-L03 | 建造／維修中途取消、恢復、讀檔 | 扣款、退款、完工各按規則結算一次；不以取消迴圈複製資源 |
| QA-L04 | 對同一商隊搶劫、打撈再返回現場 | 貨物轉移守恆，被奪資源不重新出現；關係後果與實際受害者一致 |

### F｜戰鬥與旗艦

| ID | 操作／情境 | 預期可觀察結果 |
|---|---|---|
| QA-B01 | 固定同一敵我艦隊，切換自動／戰前編隊／有限命令候選 | 可比較護航與撤退的效果；不是只憑主觀宣稱某方案更好 |
| QA-B02 | 指定護衛旗艦，敵軍試圖牽引護衛追擊 | AI 遵守已定的護衛規則；不無故離開保護目標，威脅可見 |
| QA-B03 | 下令撤退並追蹤旗艦與後勤艦 | 撤退命令可執行，有可讀路徑與代價；不保證永遠成功，也不只是動畫按鈕 |
| QA-B04 | 分別摧毀非旗艦、旗艦；再測到家與沉沒同一步 | 非旗艦損失不自動結束整局；旗艦沉依規則 Game Over；同一步競爭按事先定義順序處理 |

### H｜自由度、介面與範圍

| ID | 操作／情境 | 預期可觀察結果 |
|---|---|---|
| QA-U01 | 選擇繞道、回頭、進紅區或不急著回家 | 不被隱藏單向劇情牆攔住；仍要面對燃料、戰鬥與時間後果 |

## 另外三個遊玩實驗（不是通過／失敗單元測試）

**EXP-A：戰鬥控制。** 相同敵我配置分別測全自動、戰前編組和少量戰中命令。記錄玩家能否說明旗艦為何受損、哪次命令有效，以及需要操作多少次。若所有模式都只剩看動畫，先修行為回饋，不加新艦種。

**EXP-B：航程選擇。** 固定同一初始快照，提供貿易捷徑、採集繞路與戰鬥突破。先讓測試者自由選擇，再請其嘗試另一條；觀察不同策略是否成立。不是要求三條成本完全相同，也不因有人喜歡直奔家鄉就判定探索失敗。

**EXP-C：接管節奏。** 固定地圖和開局，只更改一個接管速度或任務權重。比較預警是否足夠、停留是否有合理收益、被追時能否指出原因。所有參數屬測試預設；沒有實測前，不寫「最佳值」或固定成功率。

## 測試紀錄模板

每次實測複製下列欄位，缺資料填「未測／未知」，不能填零冒充：

| 欄位 | 內容 |
|---|---|
| case_id / experiment_id | 對應上表 |
| build_commit / schema / content_version | 實際執行的版本 |
| world_seed / fixture / initial_state | 可重現的初始條件 |
| input_sequence / world_time | 操作順序與遊戲時間 |
| platform / browser / hardware | 實際測試環境，不假定其他設備也通過 |
| expected / actual | 預期與實際分開記錄 |
| evidence | 日誌、存檔、截圖或重現步驟 |
| result | Pass / Fail / Blocked / Not run / Deferred |
| next_action | 最小修正或下一個實驗 |

效能測試記錄幀耗時分布、模擬耗時、指令延遲與艦隊數；最終門檻依選型與目標平台再決定，不提前承諾 100 艘必定 60 FPS。截圖能證明畫面，不能單獨證明 AI 正確、存檔可靠或玩法有趣。

## 何時能擴充內容

先讓一個縮小航段完成「讀舊圖 → 選路 → 補給／作戰 → 面對接管 → 活著抵達」，再逐步擴充地標。不要求把未採納的 32 個案例全做完才准試玩，但任何資料損壞、人口／資源複製、旗艦 AI 無法控制的明顯問題，都不應用更多內容蓋過去。

早期應可離線跑完固定測試快照；生成式 AI 畫圖是製作方式，不代表玩家遊玩時要付 API 費或等待模型回覆。多人、雲端帳號、跨平台鎖步、完整 4X、十萬人角色模擬與所有古代彩蛋，不因這張清單新增為原型需求。

本頁案例數量是文件範圍，不是已通過測試數；真正的結果須依上方模板另記。
