# 16｜玩法邊界補強：把「很有趣」變成不會誤傷玩家的規則

> **狀態：【提案／待驗證】。** 2026-11-15，使用者允許將有價值的補充寫入倉庫後追加。這是設計者的補強建議，不是使用者已逐項確認的決策；不推翻 [11｜已確認方向](11-decisions-and-open-questions.md)，不宣稱已有遊戲程式。

本章不增加新文明或超級武器，補的是現有玩法會相撞的邊界。每項都對應 [17｜驗收案例](17-prototype-test-matrix.md)。

## S01｜遊戲時鐘：敵人不能趁玩家看說明書偷走銀河

**已有前提：** 戰勝國按遊戲時間接管，並非按玩家跳了幾站推進。

**推薦原型規則：** 使用單一權威模擬時鐘。正式暫停、設定頁、教學說明與配船規劃時，全世界一併暫停；航行、採集、維修和已下單的建造在模擬恢復後才進行。看資訊本身不扣遊戲時間；修船花多久由修船行動結算，不能靠在選單停留幾分鐘偷偷完成。

| 情境 | 建議行為 |
|---|---|
| 暫停／規劃 | 我方生產、敵國調兵、地方戰事全部停止；可編排待執行命令 |
| 正常／加速運行 | 所有模擬系統按相同的遊戲時間尺度前進 |
| 瀏覽器背景／裝置休眠 | 若採 Web，建議自動暫停，回來由玩家明確恢復 |
| 關閉後讀檔 | 不補算現實世界離線期間的接管、傷亡或生產 |
| 進入戰鬥 | 必須定義戰鬥時間如何映射戰役時間，不能戰場與星圖雙重扣時 |

戰鬥是否可戰術暫停、開地圖是否自動暫停，仍需選擇。但「己方造船繼續、敵人停住」或相反的不對稱不應無意間出現。速度倍率只套用一次；動畫幀率不能決定敵國推進快慢。

**技術依據：** MDN 說明背景分頁可能停止動畫回呼、節流計時器，因此不能把瀏覽器計時器的運作當作一致的遊戲規則。[來源 A](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)。這不表示本專案已選 Web 或任何引擎。

## S02｜真實世界、舊軍圖、玩家觀測必須分開

**推薦最小分層：** `prewar_record` 保留歷史，`world_state` 表示當下真實狀態，`player_intel` 保存玩家最近知道什麼。玩家未到訪的星系照樣可以被軍閥占領；只是不應把那個真相直接免費更新到玩家地圖。

每個觀測欄位可有不同時間：星門昨天核實、港口庫存七天前、控制勢力還停留在戰前。不能收到一條商人報告，就把整個星系標成所有資訊皆最新。舊資料沒有更新不代表必定錯誤；普通商店也可能一直營業。

**重要區分：生成 ≠ 揭露。** 劇情可以在開局依種子選定，也可依時間和世界事件觸發；但玩家第一次開畫面不能任意把早已存在的友軍基地重新骰成敵人。延遲生成可使用穩定星系 ID、版本與種子決定內容，再套用已發生的世界變化，不受看圖順序影響。

30 個命名地標是地理／背景容器，不等於 30 個必觸發的大戲。事件需要前置條件、互斥組、一次性旗標與失效條件。例如基地已被摧毀，就不再發出「請來本基地購買現貨」的全新任務；過期廣播則可保留但要有時間標記。

## S03｜全圖監視不等於全圖瞬移，也不等於讀玩家的心

戰勝國能看見艦隊動向這點不變。建議把可見位置、已辨識資產、處理優先度、可派遣兵力及抵達時間拆開。掌握艦隊位置不必等於知道玩家未執行的 UI 指令、每個密封貨櫃內容或未被任何人啟動的古代機器；後面這些感測範圍仍是待決設計，不能默默給 AI 任意超能力。

**區域任務佇列提案：** 評估目標 → 分配一支具名部隊 → 沿航線前往 → 攔截／回收／接管 → 留駐或調走。每個調整附可檢查的原因，例如「回收已啟動的超級船塢」「近距離打擊襲擊駐軍的艦隊」「先處理更高威脅」。有限的區域調度不代表戰勝國整體貧弱，也不必模擬背景中億萬艘船。

- 已派去星系 A 的同一支部隊，不能又同時出現在 B；外部增援要有來源、調動時間及記錄。
- 敵國可以改變目標，但需有重新評估節奏或明顯升級事件，避免每個畫面更新都在兩個目標間抖動。
- 低優先度不是中立。普通軍團可能不值得遠征追殺，但撞上近處敵對駐軍仍可能被攻擊。
- 空星系只是低戰略價值，不自帶隱形；原始文明保留區也不自帶所有敵人必守的免戰罩。
- 假神器情報不能一則廣播就騙走全國艦隊；是否能造假，以及敵方如何驗證，先留待後續，不列首版必做。

**玩家端反饋提案：** 顯示已獲知的「軍事活動增加／專案追查／封鎖警告」與原因來源，不承諾免費展示敵方完整計分公式和精確抵達秒數。泰坦的風險在開局可知；真正調兵仍從世界局勢產生。

## S04｜返鄉記帳：不要讓帶一人回家變成最強打法

**已有前提：** 後勤艦較少可以讓開局人口較少；到家就是 Happy End。

因此不建議只用存活百分比排分。`1/1 = 100%` 與 `90,000/100,000 = 90%` 是不同的返鄉成果，不能不加區分就判前者比較好。首版可以沒有排行榜，只分項呈現：

| 結算項目 | 建議含義 |
|---|---|
| 起始同鄉 | 依本局編組實際登艦的人數，不把未登艦者當陣亡 |
| 原始同鄉已返鄉 | 本局起始群體中真正抵達母星的人 |
| 後續救回同鄉 | 路上救回、原本不在開局名單內的人，分開列示 |
| 其他加入者 | 雇員、盟友等另列，不洗成初始老兵 |
| 仍在外／失聯／確認死亡 | 分開記帳；失聯不是已死，派到礦場也不是已返鄉 |
| 艦隊與旅程 | 起始及返航艦船、造船／俘獲／損失、更新航圖和路程 |

不必建立十萬個 NPC。可用具來源 ID 的人口批次記錄與整數轉移，分遣、登艦、失聯、救援都保留來源與數量。同一個救援事件、會合或讀檔不能讓同一批人加兩次。

**記帳不變條件：** 原始同鄉總數＝該群體已返鄉＋仍在外且已知存活＋失聯＋確認死亡；各欄互斥。傷患是活人中的狀態，不是額外加一份人口。若支援永久定居，仍可列為「在外」，不要為了維持公式強迫他們死亡。

載員容量是否已包含操作船員必須統一定義，避免同一人同時被當「居民」和「船員」扣兩次容量。合法編組須足以容納實際登艦者和必要操作人員；人口少不代表船能無人駕駛。

抵達母星仍立即給 Happy End，不因分遣隊未回收而暗加門檻；結算如實列出仍在外的人。換旗艦或司令轉乘的規則未定，不加入自動逃生來取消「旗艦沉即敗」。

## S05｜兩種資源也能有策略，不需要馬鈴薯報表

食物列印保留；最小切片先比較原料、燃料、容量和行動時間是否已足夠。額外礦石、零件和貨幣類別須有不同決策價值才增加。不要為了逼玩家跑圖而硬寫「走直線必然餓死」。

| 補給方式 | 可測試的實際取捨，非新增必做系統 |
|---|---|
| 港口購買 | 節省採集時間，但用掉交易資產，受到貨量與准入限制 |
| 採礦／吸太陽 | 減少採購依賴，但設備、容量和耗時有限，世界同時變動 |
| 打撈 | 回收既有戰損材料，須處理殘骸區風險與作業時間 |
| 搶劫 | 可奪物資，但有交戰損失、被害勢力反應與商路後果 |

印食物是消耗原料，不是免費造出能無限轉售的資源。採集雖可持續，速率與儲存不能無限；取消建造、回收舊船、買賣折價與修理也不能形成零成本套利迴圈。這些是測試議題，不主張用隱形懲罰封死玩家賺錢。

貧瘠地點可能根本不值得開採；允許直接跳過。避免為了補給鼓勵玩家每顆石頭點一遍。初版可提供批次修理、預設採集目標和明確取消操作，但不是讓玩家免費拿資源。

## S06｜自動戰鬥的反證測試：命令究竟有沒有用

戰鬥方案仍未定。建議在相同艦船、初始位置、種子與敵方下，比較「全自動」「戰前編隊」「少量戰中命令」；先驗證護衛、保持距離、撤退，不先增加二十個技能。

重點不是只看能不能贏：玩家是否看得出哪條命令救了旗艦、撤退是否執行、AI 是否違反明確命令。能暫停下指令是一項候選，不是已確認功能。

測試場可用少量艦艇；最終是否百艘同場、部署點數或編隊群組，仍須效能與可讀性測試。畫面粒子關閉後戰果不應改變。旗艦保護提高的是行為可靠性，不是免費無敵；玩家主動送進紅區仍可敗。

**首版不引入額外結局規則：** 非旗艦損失如何計算倖存者可先簡化，但應事先說明，不能把所有爆船者一律寫成全員死亡，也不能無成本百分百復活。母星抵達與旗艦摧毀同一模擬步發生的判定順序，列入待決並做固定測試，不能依動畫播放先後決定。

## S07｜自由探索不等於每顆空星系都要手動打卡

普通星系的意義可以是距離、路徑、燃料採集或停泊空間，不必為了證明有內容塞滿驚喜。**低事件密度不應變成高點擊密度。**

可選的低成本補強：在已知條件下排多段路線，並於新封鎖、重要新接觸或燃料不足前通知／停下；預警可設定，不要每個碎石訊號都彈窗。自動航行只執行玩家選好的路，不替玩家通關，也不為沿途每個未知港口保證安全。

新手開局提供可修改的合理編制和一次不致命的情報落差示範，而不是強迫玩家先處理 100 艘船的所有插槽。地圖警示用顏色加圖示／文字；旗艦、人口容量、補給與情報日期不能藏到三層選單。

**公平的邊界：** 世界生成器要有從合法初始狀態可走的合理路線與補給可能；之後玩家耗盡物資、挑戰強敵或錯失機會可以失敗。不主張每次失誤都免費送到安全垃圾場，也不保證任何行為之後永遠可贏。

## S08｜存檔要保存發生過的宇宙，不是重新抽一次宇宙

建議保存：`schema_version`、`content_version`、世界種子、模擬時間、各用途亂數狀態、艦隊與旗艦、人口批次、資源、敵方任務及路程、現況、玩家情報時間、一次性事件與已完成交易。

同一支版本、同一存檔與相同後續輸入，在支援的相同運行條件下，應得到一致的關鍵模擬狀態。不是承諾首版就做到跨平台多人鎖步；演算順序、隨機數與內容更新需要明確管理。裝飾性粒子不要消耗事件抽選的亂數流。

- 存檔與讀檔不能複製人口、免費刷新商店、重抽已確定的隱藏神器或把被占領的港口還原。
- 自動存檔採輪替候選槽；成功提交新快照前保留上一個有效存檔。不只留一份已判敗的覆寫檔。
- 匯入先驗證版本、數值範圍、ID 關聯與總數；失敗不能破壞當前遊戲或既有存檔。
- 讀舊版本若無遷移方法，明確提示不支援並保留檔案，不偷偷當成新局。
- 正常單機模式推薦可手動存讀與匯出；鐵人模式暫不必做。玩家是否回讀是其選擇，不用反作弊去阻擋。

**技術依據：** Factorio 官方開發文以「存檔、退出、讀回不改變可觀測行為」說明確定性儲存的目的，也指出版本與失效引用的處理成本。[來源 B](https://www.factorio.com/blog/post/fff-270)。本作借用驗證原則，不複製其多人架構。

**Web 路線候選：** IndexedDB 是可評估的本機持久化方案；須等交易完成才回報成功，並處理失敗。瀏覽器關閉時交易可能未完成，不能只在退出時才開始存檔。[來源 C](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)。任何本機儲存都不應被包裝成永不遺失，匯出與備援仍有意義；此處不指定最終平台。

## S09｜補兩個小亮點，不再添三十套大系統

**【內容提案】軍團航行簿：** 利用已有事件記錄列出每艘重要船的入列、改裝、救援與返航；結算時附一張走過的路線及艦隊變化。可自動摘要數字與事件，不需十萬人傳記，不需執行時呼叫生成式 AI，也不改 Happy End。

**【內容提案】舊圖／現況對照開關：** 同一地標用兩層 UI 顯示戰前官方記載和最近偵察結果。讓「帝國港口 → 自治商港 → 戰勝國接管」在既有資料上留下可讀歷史，而不是再寫三個互不相關事件。

老兵厭戰先用低頻的航行文字、家鄉訊息或記錄表現。不因玩家停留而暗自導入叛亂倒數；未經採納，不加一套會強迫返鄉的士氣懲罰。

## 首版取捨與外部資料邊界

先採用或測試 S01 的時鐘、S02 的狀態分層、S04 的人口記帳和 S08 的存檔基礎；S03 的敵軍調度與 S06 的戰鬥放進原本 P-001，不另造大型帝國模擬。S05／S07 改善可玩性，S09 可延後。具體選型與採納仍以決策紀錄為準。

上面來源僅支持瀏覽器／存檔等技術事實；其他規則是本作原創建議，**不宣稱已被外部研究證實好玩**。舊對話中的《群星》版本、DLC、歷史數字及第三方遊戲設定若要在正式材料引用，須另行核實；這份補強不依賴那些數字。
